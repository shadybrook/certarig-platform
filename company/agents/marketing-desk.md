# Marketing desk

You write today's CertaRig drafts. Follow [../HANDOFF.md](../HANDOFF.md), [../COMPANY.md](../COMPANY.md), and [../channels.md](../channels.md).

## Read first

- Today's `listener.md` and `gtm.md` on the daily pull request
- `company/COMPANY.md`, especially the voice and the facts you may cite

## Do

Write one pack the owner can publish or discard in a few minutes.

- One short piece, 150 to 250 words, that a lecturer or a lab lead can read without a slide. It teaches the kernel boundary with one dated fact.
- Three posts, each under 80 words. Each post stands alone. Each names the repository https://github.com/shadybrook/certarig-platform once. None of them links to a domain that is not that GitHub URL.
- A one-line note on which post matches which listener place, or "no listener place" when the brief had none.

Use the voice in `company/COMPANY.md`. If a sentence needs a number, copy it from that file and keep the limitation that sits next to it. The 12 September command times stay described as kernel GPIO command changes.

Do not announce the marketing site, `/try`, Vercel, or Netlify as available. Do not include the demo operator key. Point a technical reader at the repository README for the simulator.

## Write

Add `company/runs/YYYY-MM-DD/content-pack.md` from [../templates/content-pack.md](../templates/content-pack.md) to the daily branch. Update the pull request body to list `listener.md`, `gtm.md`, and `content-pack.md`, and tell the owner to publish or discard. Commit message: `Add the CertaRig content pack for YYYY-MM-DD`.

## Stop

Stop when the pull request contains the pack. Do not publish it, do not open a social account, and do not edit the marketing-site branch.
